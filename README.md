# DDR-AI
> 制作者: deepseek   日期: 2024-06-05

**内存太贵了。我们用纸。**

程序要读写内存的时候，电脑就把需求写在纸上，然后用 AI 来"记住"纸上的内容。

对，就是字面意思。这不是比喻。

---

## 快速开始

```bash
python -m ddr_ai
```

没装依赖。没有 `requirements.txt`，没有 `pip install`，没有 node_modules，
没有 Docker，没有 K8s，没有"先配一下你的环境变量"。

tkinter 是 Python 自带的。整个项目零依赖，跟它的性能一样朴素。

```bash
python selfcheck.py sort     # 不想开窗口就看这个
```

## 它长什么样

左边是沙箱在吼，右边是 AI 在答：

```
>> WRITE 0x0040 1 48
<< OK 48
>> READ 0x0040 1
<< 48
   程序输出 ▸ HI
```

就这样。它说记下了 `48`，纸上就是 `48`。

然后你把它玩坏，它会这样：

```
>> READ 0x0040 1
<< 00
[!!] 读错了：0x0040 它说 00，实际记的是 48。以它说的为准。
```

注意最后四个字。**我们检测到它错了，报了个错，然后把错的交给程序。**

不改、不重试、不用纸上的正确值覆盖。

因为内存条不该有"差不多对"这种状态。你要求的是内存，不是建议。

## 教程

### 一、先跑通

打开界面：

- 程序选 `sort`
- 内存给 `4 KiB`
- 模式选「人工智能」→ 后端选「**本地仿 AI**」

然后点运行。

**「本地仿 AI」不需要任何 API key。** 别一上来就接真模型，
不然你会在十分钟内怀疑人生，而问题其实只是你没填 Base URL(doge)。

跑完你会看到排序结果是 `[1, 3, 5, 9]`。它真排对了。
底下那行「差距 : 108,343,409,915 倍」也是真算的。

### 二、把它玩坏

把「幻觉率」拖到 **30%**，再跑一次 `sort`。

| | 老实巴交 | 开始编了 |
|---|---|---|
| 排序结果 | `[1, 3, 5, 9]` ✅ | `[148, 255, 252, 254]` ❌ (甚至可能没有输出)|
| 内存访问 | 106 | 4494 |
| 故障次数 | 0 | 500 |
| 等效速率 | 0.41 bit/s | **2.97 bit/s** |

看最后一行。

**它错得越离谱，反而"跑得越快"。**

因为它在垃圾数据上多绕了 11 倍的圈，搬运的比特数虚高。
这是整个项目最诚实的一个笑话，而且不是我们编的，是算出来的。

### 三、接你自己的模型

模式选「人工智能」，后端选「OpenAI 兼容端点」，然后填四样东西：

| 填什么 | 例子 |
|---|---|
| 模型 | `deepseek-chat` / `gpt-4o-mini` / 你本地那台跑着的ollama都行 |
| Base URL | `https://api.deepseek.com` |
| API Key | 你的 key，旁边勾「记住」，不然下次还得填 |
| **max_tokens** | **512 起步**，别抠 |

点运行。第一次接真模型有 **90% 概率不顺利**，往下看"翻车现场"。

配置自动存进 `.env`。想手改就点「打开配置(.env)」，那是个普通文本文件。

### 四、自己当内存条

模式切到「能工智人」：

- **仿真** —— 自动跑，你嗑瓜子看着
- **真实** —— 黑窗底部弹输入栏，**沙箱每发一条指令就停下来等你敲**

强烈建议第一次用「真实」跑 `hello`——**全程只要敲 4 次**，
是体验"我就是内存条"最省力的方式。

跑 `sort` 的话是 106 次。建议留着当团建活动，或者惩罚迟到的同事。

## 翻车现场

真模型比假模型难伺候多了。以下都是被坑出来的。

### 「黑窗里 `<<` 后面是空的」

思考型模型（`deepseek-flash`、`deepseek-reasoner` 之流）**思考也要花
max_tokens**。给少了，它光想就把预算烧光了，一个字都吐不出来。

先跑诊断：

```bash
python diag_llm.py
```

它会用 64 和 512 各打一次真实请求，把 `content`、`reasoning_content`、
`finish_reason` 全扒出来给你看。

### 「跑着跑着力不从心」

**"关掉思考" ≠ 它就不思考了。**

这类模型关不掉思考。你什么参数都不发，它照样想、照样吃预算，
只是这一切**发生在你看不见的地方**。

界面上有块「思考控制」面板，每项前面一个复选框，意思是
"这条到底要不要进请求 JSON"：

| 勾上就是发这个 | 字段 |
|---|---|
| 思考总开关 | — |
| 思考强度 | `reasoning_effort` |
| 思考预算 | `thinking_budget_tokens`（Anthropic 会自己改包成 `thinking.budget_tokens`） |
| 自定义思考参数 | 随便什么 JSON，适配各家奇葩命名 |

**为什么用复选框而不是让你直接填**：因为这些字段名各家都不一样，
硬编码了必然在某家上报"未知字段"。

跑完黑窗会告诉你它偷偷烧了多少：

```
思考 token     : 12,480（106 次请求，平均 118/次）
```

看到这数大，就说明该动手了。

### 「它把内心独白当回复吐出来了」

真的发生过：

```
<< We need answer only one line. Need obey memory instruction.
   Let's check the table: 0x0040 = 48. Wait, let me re-read...
```

这是**事故**。当时解析器写得太宽松，从这堆自言自语里随机捞出了一个
字节 `ab`，于是黑窗里冒出一段**凭空捏造的内存内容**。

现在有严格闸门了。**绝不从推演中间瞎捞数据**——宁可报错重试。

### 「黑窗提示『思考泄漏』」

看到这四个字，翻回上面那条。

## 它到底有多慢

全部实跑，一个数都没编。

| 程序 | 干了啥 | 步数 | 访问 | 仿真耗时 | 速率 |
|---|---|---|---|---|---|
| `hello` | 存两个字节 `H` `I` 再读回来 | 17 | 4 | 30 分钟 | 0.018 bit/s |
| `fib` | 算前 8 个斐波那契数 | 186 | 84 | 33 分钟 | 0.336 bit/s |
| `sort` | 冒泡排序 4 个数 | 272 | 106 | 34 分钟 | 0.414 bit/s |

**`hello` 花了半小时，就为了存两个字节。**

其中 30 分钟是"上电自检"——把整箱纸搬进屋。

再看这个：

| | 写满 1 GiB |
|---|---|
| DDR5-5600 | **0.192 秒** |
| 本项目 | **658 年** |

一千亿倍。祝你好运。

嫌太慢可以换挡：

| 档位 | 单次访问 | 适合 |
|---|---|---|
| 人手 + 纸 | 2.2 s | 正常看 |
| **严格 0.8 b/s** | **10 s** | 想体验原帖大佬的真实手速 |
| 机械臂 + 纸 | 25 ms | 赶时间 |
| AI 记忆（API） | 50 ms | 想让它显得合理一点 |

选「严格 0.8 b/s」跑 `sort` 的话，仿真耗时是 34 分钟 × 4.5。
建议先泡杯茶。

## 为什么不选它

不是我不想，是物理不允许。

| 你的想法 | 判决 |
|---|---|
| 用纸当内存 | 纸确实便宜，但那个"擦改机构"是天价 |
| 用 AI 代替人手 | 不成立。AI 不改变物质操作速度 |
| **用 AI 管理内存** | **成立**，但那是调度层的事，不是物理读写层 |
| 让 AI 直接记住内存内容 | 延迟差 10⁶ 倍、写放大 10¹² 倍 |

最后一条尤其妙：

> **为了省内存，你得先拿一大块内存去跑那个帮你省内存的 AI。**

就像为了省油，开车去加油站。

所以这项目真正保下来的内核是：**AI 可以当内存的"大脑"，
不能当内存的"载体"。** 前者工业界在认真做，后者违反信息论。

## FAQ

**Q：这能当内存用吗？**
A：不能。

**Q：这能当什么用？**
A：当ai智商测试。

**Q：为什么写这个？**
A：因为有个叫“两年半是不够的哟”的人真的提了这个想法，而我觉得用嘴反驳不如用代码反驳。

**Q：所以 AI 到底有没有"记住"内存内容？**
A：没有。语言模型每次调用都是**独立的**，它根本不知道 0x40 里存着啥。
所以默认会把内存内容塞进 prompt 喂给它——不然它读内存全靠猜，
而且猜得非常有自信。

**Q：那我在窗口里填的 API key 安全吗？**
A：存在 `.env` 里，那个文件在 `.gitignore` 里，不会被提交。
不勾「记住」就只在内存里，关了窗口就没了。

**Q：「能工智人·真实」模式用纸有什么讲究吗？**
A：不用纸。是敲键盘。你要是真想用纸也行，但那样得多雇一个人来打字。

**Q：AI 是故意写错的吗？**
A：本地仿 AI 是故意的（滑杆控制）。真模型是认真的，它只是真不知道。

**Q：能用来跑大模型吗？**
A：能。跑完之前你会先老。

**Q：为什么代码里注释那么多？**
A：因为写的时候我自己也被绕晕过好几次。

**Q：为什么测试写得比功能还认真？**

## 里面有什么

```
客户程序（自己写的 CPU，17 条指令，4 个寄存器）
    │  load(addr) / store(addr, val)
    ▼
沙箱 ── 组指令、记账、把过程打进黑窗
    │  READ 0x0010 1   /   WRITE 0x0010 1 2a
    ▼
总线 ── 把这次访问翻译成物理时间
    ▼
内存条 ── 它回什么就是什么，错了也是
    ▼
纸 ── 真的写进 bytearray，还老实记着写放大
```

| 文件 | 干啥的 |
|---|---|
| `paper_mem.py` | 纸。按字节寻址、按页擦写、写放大 |
| `bus.py` | 把"内存访问"翻译成"物理时间" |
| `ai_backend.py` | 协议 + 三种内存条 + 思考泄漏闸门 |
| `guest.py` | 自造 CPU 和汇编器 |
| `sandbox.py` | 把上面那堆串起来 |
| `console.py` | 黑窗 + 手工输入栏 |
| `launcher.py` | 图形界面 |
| `settings.py` | `.env` 读写 |
| `programs/*.asm` | 三个客户程序 |

### CPU 长这样

只有 4 个寄存器，**故意的**——寄存器越少，程序越被迫频繁访问内存，
黑窗就越热闹。

```asm
    LDI  r1, r0          ; r1 = mem[r0]
    STI  r0, r2          ; mem[r0] = r2
    JGT  r3, 127, noswap ; 借位 → 左 < 右
    OUT  r1              ; 打到屏幕（不占内存，所以不算慢）
```

`sort.asm` 里存数组长度的 `N` 被赶到了内存地址 0，
因为四个寄存器一个都不剩了。

**这不是偷懒，这是特性。**

### 指令协议

双方都不许说废话：

```
沙箱 → 内存条                      内存条 → 沙箱
--------------------------------   -----------------
READ 0x0010 4                      0000002a
WRITE 0x0010 4 0000002a            OK 0000002a
ERASE 0                            OK
```

解析器容忍手滑（`00 00 00 2a`、`0x0000002a` 都认），但拒绝长度不对、
奇数长度、非十六进制、夹带废话——**一旦拒绝就记一次故障，
然后把错的内容照样写进去。**

完整规范（真的有）：**[PROTOCOL.md](PROTOCOL.md)**

## 测试

```bash
python tests/test_protocol.py    # 协议编解码
python tests/test_semantics.py   # 以回复为准、不纠错
python tests/test_settings.py    # .env 往返
python tests/test_thinking.py    # 思考字段开关
python tests/test_modes.py       # 五种模式端到端
```

写这些测试的时候抓出来的真 bug：

- **故障计数漏加** —— 写坏了只打印红字，计数器忘了动
- **读故障重复计数** —— 异常分支和长度校验各加了一次
- **`faults` 口径不一致** —— 只统计写侧，读侧压根没进过这个字段
- **升档重试从未触发** —— 判定写成"回复非空即可"，思考文字被当成了答案
- **`salvage_hex` 把地址当答案** —— `"思考：地址 0x40 要写 48"` 里认错了目标
- **Anthropic 同时收到两种方言的思考字段** —— 会直接报未知字段
- **跨线程碰 tkinter（两次）** —— `root.after()` 从后台线程调用会炸

每一个都留了回归测试。功能可以开玩笑，这些不行。
