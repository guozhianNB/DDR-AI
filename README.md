# DDR-AI · 纸介质内存沙箱

> 内存越来越贵，所以有人想到用纸代替内存颗粒。
> 这个项目把那个想法做成了能跑的沙箱：**纸是介质，AI 是内存条，黑窗是总线。**

这是一个整活项目。但整活的规矩是：**外壳可以荒诞，里面的数字不许编**。
所以这里的每一次内存访问、每一纳秒延迟、每一次页重写、每一次 AI 幻觉，
都是真的算出来、真的发生、真的把程序跑崩的。

---

## 它长什么样

启动后是一个选程序的窗口，核心是「谁来当内存条」二选一：

```
┌─ DDR-AI · 纸介质内存沙箱 ───────────────────────────────────┐
│  1. 选择要运行的程序   [ sort        ▾ ] [打开目录…][查看源码]│
│  2. 给它多少内存       容量 [4 KiB ▾]   页大小 [128 B ▾]      │
│  3. 谁来当内存条   (•) 人工智能      ( ) 能工智人            │
│                                                              │
│  ┌ 3a. 人工智能 · 接口配置 ──────────────────────────────┐  │
│  │ 后端 [OpenAI 兼容端点 ▾]      模型 [gpt-4o-mini      ] │  │
│  │ Base URL [https://api.openai.com/v1                  ] │  │
│  │ API Key  [••••••••••••]  ☐显示                         │  │
│  │ temperature ━━━●━━━━━  0.00                            │  │
│  │ 自定义请求 JSON [{"top_p": 0.9}                      ] │  │
│  │ 幻觉率 ━━━━━●━━━━  30% —— 经常记错，结果基本不可信     │  │
│  └────────────────────────────────────────────────────────┘  │
│                                                              │
│  [▶ 运行] [■ 中止] [清空黑窗] [查看指令流] [性能对比]         │
├──────────────────────────────────────────────────────────────┤
│  ██ 黑窗：沙箱与内存条的每一次问答都在这儿刷 ██              │
└──────────────────────────────────────────────────────────────┘
```

程序输出是**实时**刷进黑窗的：`OUT` 每产出一个字节就立刻显示，
不等程序跑完。所以你能看到「读一个字节 → 打一个字符」的因果顺序：

```
>> READ 0x0040 1
<< 48
>> READ 0x0041 1
<< 49
   程序输出 ▸ HI        ← 跑到这里就出现了，不是最后才倒出来
```

收尾报告里不再重复这份输出（`[程序输出]` 那行已去掉）——
同一份输出出现两遍会让人以为是两次不同的结果。收尾只报结果与指标。

## 两个模式

### 人工智能 —— 让模型记忆内容

| 后端 | 说明 |
|---|---|
| **本地仿 AI** | 零依赖、确定性、不要 key。幻觉率滑杆对它有效 |
| **OpenAI 兼容端点** | OpenAI / DeepSeek / 本地 vLLM / Ollama…填 Base URL 即可 |
| **Anthropic** | Claude Messages API |

接真模型时，**Base URL、API Key、模型、temperature、自定义请求 JSON 全在窗口里填**，
不用碰环境变量。自定义 JSON 会深合并进请求体，可以覆盖任何字段：

```json
{"top_p": 0.9, "seed": 42, "stop": ["\n\n"]}
```

### 无状态模型：必须给上下文

**这是最容易踩的坑。** 语言模型的每次 API 调用都是**独立的、无状态的**——
它不记得上一次请求。所以如果你只发 `READ 0x0040 1`，它没有任何信息可依，
只能瞎猜，于是：

```
>> WRITE 0x0040 1 48
<< OK 48
>> READ 0x0040 1
<< 00
[!!] 读错了：0x0040 它说 00，实际记的是 48。以它说的为准。
```

**这不是模型不聪明，是架构上它根本不知道。** 写能成功只因为 `WRITE` 指令
自带数据（回声即可），`READ` 只有地址，它无从知道那个地址里是什么。

所以默认会**把内存内容随每次请求发给它**（`state` 模式），prompt 长这样：

```
【当前内存内容】
0040: 48 49 00 00 00 00 00 00 00 00 00 00 00 00 00 00  HI..............
0050: 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00  ................

上表是内存的权威内容。READ 必须照表回答，WRITE 必须回显你写入后的值。

【本次指令】
READ 0x0040 1
```

界面上「上下文」下拉框有三种模式，实测对照（`tests/test_modes.py` 模式 3d）：

| 模式 | 给什么 | sort/hello 实测 |
|---|---|---|
| **state** | 内存内容的十六进制转储 | 读对，`[72,73]`，故障 0 ✅ |
| recent | 只给最近几次收发记录 | 省 token，读全量状态时仍可能错 |
| none | 什么都不给 | 读全错，`[0,0]`，故障 2 ❌ |

代价是 token：4 KiB 内存的转储约 3~4k token。所以有个
`context_max_bytes`（默认 2048）上限，超了就只发焦点地址附近的节选。

真模型的每次回答都可能不同，所以幻觉率滑杆对它无效——
**它会自己决定说不说实话**，只不过现在它至少有信息可说了。

#### 思考型模型注意：把 max_tokens 调大

`deepseek-flash`、`deepseek-reasoner` 这类**思考型模型**，思考过程也吃
`max_tokens` 预算。给太小（比如 64），它光想就把预算烧光了，正式回答
一个字都吐不出来——你会在黑窗里看到**空的回复**和"读数不合规：它给了 (空)"。

程序已经做了四层处理：

| 情况 | 处理 |
|---|---|
| 答案在 `reasoning_content` 里、`content` 为空 | 自动回退去读 `reasoning_content` |
| 短推理里夹着答案（"让我看看……2a"） | 从**结尾**捞出十六进制，长推演一律拒绝 |
| 想完了没力气回答（`finish_reason=length`） | 自动升档到 4 倍 max_tokens 并禁止思考重试 |
| **把整段思考当正文吐出来** | 判定不可用，升档重试——**绝不从中瞎捞数据** |

最后一条是真实事故：模型曾把整段英文推演当回复吐出来，旧的宽松解析
从中随机捞出一个字节 `ab`，于是黑窗里出现了凭空捏造的内存内容。
现在有严格闸门：严格回复必须**整条**都是数据；回退路径要求结尾是
干净的十六进制 token 且总长 ≤ 40 字符。

还有一个设计修正：`state` 模式下**不再同时附上【最近的操作】**。
之前两份都给，模型要在"权威表"和"操作流水"之间自己调和，
结果它开始虚构第三份内存内容开始自我辩论。

但你**仍然应该把 max_tokens 调到 512 以上**——因为自动升档意味着每次内存
访问要发两次请求，延迟直接翻倍。界面上的 `max_tokens` 就在 temperature 右边。

排查工具：

```bash
python diag_llm.py              # 打一次真实请求，挖出原始返回字段
```

它会分别用 `max_tokens=64` 和 `512` 各打一次，直接告诉你 content /
reasoning_content / finish_reason 分别是什么。**回复是空的时候先跑这个。**

#### 思考控制：关掉思考 ≠ 它就不思考了

"跑着跑着力不从心"通常就是这个原因：模型在**暗处**烧预算。

`deepseek-flash` 这类模型**关不掉思考**。你不发任何思考参数，它照样想、
照样吃 `max_tokens`——你看不见这个过程，只看到它后面越来越答不动。

所以界面上有一整块「思考控制」面板，**每个字段前面一个复选框**，
表示"这条要不要进请求 JSON"：

| 复选框 | 字段 | 说明 |
|---|---|---|
| 思考总开关 | — | 关掉后按「关闭时发」处理 |
| 关闭时发 | 自定义 JSON | 留空 = 请求里完全不提思考字段 |
| 思考强度 | `reasoning_effort` | OpenAI 系吃 `low`/`medium`/`high` |
| 思考预算 | `thinking_budget_tokens` | Anthropic 会自动包成 `thinking.budget_tokens` |
| 自定义思考参数 | 任意 JSON | 适配各家不同字段名 |

**为什么要用复选框而不是直接填**：各家模型的思考字段名和支持情况都不一样，
硬编码必然在某家上报"未知字段"。复选框明确表达"这个字段要不要出现"。

优先级：**「自定义请求 JSON」最高**，可以覆盖上面任何一项。

运行结束后黑窗会报出思考开销：

```
思考 token     : 12,480（106 次请求，平均 118/次）
注意：思考是隐形开销——它吃 max_tokens 但不产生回复。
```

看到这个数字很大，就说明该关思考或调小预算了。

### 配置会记住：`.env`

Base URL、模型名、API Key 这些**只需要填一次**。启动器会读写项目根的 `.env`：

| 时机 | 行为 |
|---|---|
| 启动 | 自动带出上次填的值；界面右下角显示配置来源 |
| 点「运行」 | 先把当前接口配置写回 `.env` |
| 输入框失焦、切后端、勾选变化 | 静默保存 |
| 点「打开配置(.env)」 | 用系统默认程序打开，可直接手改 |

```bash
cp .env.example .env    # 也可以手动建；不建也能用，界面里填完就会自动生成
```

密钥保护：**`.env` 已在 `.gitignore` 里**，不会进版本库。
API Key 旁边有个「记住」勾选框，默认开着——不勾就只存在内存里，运行时写入空值清掉文件里的旧 key。

> 路径用 `__file__` 锚定项目根，所以从任何目录启动都读得到，
> 不依赖当前工作目录。

### 能工智人 —— 你自己上

| 子模式 | 说明 |
|---|---|
| **仿真** | 自动跑，按「机构档位 + 节流」播放，你只管看 |
| **真实** | 黑窗弹出输入栏，沙箱每发一条指令就停下来等你手敲十六进制 |

真实模式下节流被禁用——**你的手速就是节流**。点运行前会告诉你大概要敲多少次。

## 严格指令协议

沙箱只发指令，内存条只回数据。双方都不许说废话：

```
沙箱 → 内存条                          内存条 → 沙箱
------------------------------------   -------------------------
READ 0x0010 4                          0000002a
WRITE 0x0010 4 0000002a                OK 0000002a
ERASE 0                                OK
```

约束：地址是 `0x` + 定宽十六进制（≥4 位，按容量自适应；1 MiB 时是 6 位）；
长度是十进制；数据是连写的十六进制，无空格、无 `0x`、无分隔符；
回复只有一行，不许解释、道歉、加代码块。

解析器容错（容忍 `00 00 00 2a`、`0x0000002a`、`00-00-00-2a`），但会拒绝
长度不匹配、奇数长度、非十六进制字符、夹带解释文字——

**一旦拒绝，就记为一次故障，并让它按错误内容落纸。**
因为内存条不该有"差不多对"这种状态。这比"AI 记错了但假装没事"诚实得多。

### 以回复为准，不自动纠错

沙箱会**检测并报错**，但绝不**修正**：

| 情况 | 沙箱怎么做 |
|---|---|
| 它写错了 | 原样落纸，然后报一次红字 |
| 它读错了 | 把它的答复交回程序，然后报一次红字 |
| 它给的位数不对 | 照给多少用多少，不补位，报一次红字 |
| 它完全不响应 | 读按 `0` 返回、写直接丢弃，各记一次故障 |

报错是**通知**，不是恢复机制。正常路径下黑窗里只有两行——一条指令、一条回复，
没有任何"落纸确认"之类的附注。

## 里面到底有什么

```
客户程序 (guest.py 的 CPU)
    │  load(addr) / store(addr, val)
    ▼
沙箱 (sandbox.py) ── 组严格指令、记账、把过程打进黑窗
    │  READ 0x0010 1 / WRITE 0x0010 1 2a
    ▼
总线 (bus.py) ────── 把这次访问翻译成物理时间
    │
    ▼
内存条 (ai_backend.py) ── 它回的数据就是事实，错了也是
    │
    ▼
纸 (paper_mem.py) ── 真的把字节写进 bytearray，还记着写放大
```

| 模块 | 职责 |
|---|---|
| `paper_mem.py` | 纸介质：按字节寻址、按页擦写、写放大、指标统计 |
| `bus.py` | 总线与时序档位：0.8 b/s 手写 → AI 往返 50 ms |
| `ai_backend.py` | 严格协议 + 三种内存条后端（本地仿 AI / LLM / 真人） |
| `guest.py` | 自造 CPU 与汇编器（15 条指令，4 个寄存器） |
| `sandbox.py` | 把上面几层串起来，生成对话流与最终报告 |
| `console.py` | 黑窗渲染 + 真实模式的手工输入栏（线程安全） |
| `settings.py` | `.env` 读写：接口配置持久化，路径锚定项目根 |
| `launcher.py` | 启动器 GUI（两模式） |
| `programs/*.asm` | 三个客户程序：`hello` / `fib` / `sort` |

## 客户程序

程序跑在一套自己造的 CPU 上。只有 4 个寄存器，故意的——
寄存器越少，程序越被迫频繁访问内存，黑窗就越热闹。

```asm
    ADDI r0, 1           ; r0 += 1
    LDI  r1, r0          ; r1 = mem[r0]      （间接寻址）
    STI  r0, r2          ; mem[r0] = r2
    SUB  r3, r2          ; r3 -= r2          （寄存器相减）
    JGT  r3, 127, noswap ; 借位 → 左 < 右
    OUT  r1              ; 打到屏幕（不占内存）
```

三个示例程序的输出都经过验证：

| 程序 | 做什么 | 步数 | 内存访问 |
|---|---|---|---|
| `hello` | 把 "HI" 写进内存再读回来 | 17 | 4 |
| `fib` | 滚动变量算前 8 个斐波那契数 | 186 | 约 80 |
| `sort` | 冒泡排序 `[5,3,9,1] → [1,3,5,9]` | 272 | 106 |

## 最有说服力的一组对比

同一个 `sort`，只改「本地仿 AI 的幻觉率」：

| | 幻觉率 0% | 幻觉率 30% |
|---|---|---|
| 输出 | `[1, 3, 5, 9]` ✅ | `[148, 255, 252, 254]` ❌ |
| CPU 步数 | 272 | 11594 |
| 内存访问 | 106 | 4494 |
| 故障次数 | 0 | 500 |
| 等效速率 | 0.41 bit/s | 2.97 bit/s |

注意最后一行：**内存条错得越离谱，程序反而"跑得越快"**（因为它在
错误数据上绕了更多圈，搬运的比特数虚高）。这是本项目最诚实的一个笑话。

这不是排序算法挂了，是内存条在编。

## 时序档位

| 档位 | 单次访问 | 说明 |
|---|---|---|
| 人手 + 纸 | 约 2.2 s | 誊写量级 ~2 bit/s |
| 严格 0.8 b/s | 10 s | 原帖大佬的实测手速 |
| 机械臂 + 纸 | 约 25 ms | 快 100 倍，但整页仍要重写 |
| AI 记忆（API） | 50 ms | 一次推理往返 |
| AI 长上下文 | 约 1.3 s | 整页塞进上下文窗口 |

`sort` 在「人手 + 纸」档下，仿真耗时 **34 分钟**，等效速率 **0.41 bit/s**，
而 DDR5-5600 是 44.8 Gbit/s——差距约 **1.08 × 10¹¹ 倍**。

## 几个诚实的设定

- **内存条会被无条件信任**。它说写进去了，就写进去了；它记错了，纸上就是错的。
  这是"让 AI 记忆内存内容"这个想法在工程上的真实形态。
- **页大小决定写放大**。改 1 个字节要重誊一整页，页越大越惨。启动器里可以调。
- **寄存器不够就要多跑内存**。`sort` 的 `N` 被迫存进内存地址 0，
  就是因为 4 个寄存器一个都不剩了。
- **本地仿 AI 是确定性随机**（固定种子），所以同一次运行可以复现；
  换真模型后端则每次都不一样。
- **真实模式下沙箱会真的阻塞**，等你敲完才继续——包括等你敲错。

## 接真 AI 时的环境变量兜底

优先级：**窗口里填的（存 `.env`）> 进程环境变量 > 内置默认值**。
环境变量是最后一道兜底，适合 CI 或临时切换：

```bash
set DDR_AI_API_KEY=sk-xxxx
set DDR_AI_BASE_URL=https://api.deepseek.com/v1     # 可选
set DDR_AI_MODEL=deepseek-chat                      # 可选
```
